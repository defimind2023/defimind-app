Whitepaper

The security layer every agent needs.

DefiMind Public beta November 2026 Live on mainnet

AI agents are becoming economic actors. DefiMind is what lets them spend safely. An agent can only pay through DefiMind. Every payment is checked against rules the owner sets, test-run before it is signed, and then auto-approved, sent to the owner for a passkey approval, or rejected. The agent never holds a key. Funds stay in the owner's own vault, and the agent spends from a small wallet refilled under a daily limit that the blockchain itself enforces. The most a day can cost is fixed in advance, even if our software fails.

01Why now

Agents have learned to reason, write code and use tools. The next step is obvious: they will pay for what they use. Data, compute, APIs, services, each other. Two open standards are making that real today. x402 lets any API charge per request, in stablecoins, with no account and no card. MCP gives every agent one standard way to plug into tools.

What is missing is not intelligence. It is trust. Wallets were built for people who read what they sign. An agent signs whatever it is told to, at machine speed. The agent economy needs a layer that says yes to the right payment and no to everything else, and that keeps saying no even when something goes wrong. That layer is DefiMind.

02The problem

The moment an agent can spend, a single bad instruction, a prompt injection, a bug or a leaked key can drain a wallet in seconds. Today the choice is stark: give the agent a private key and risk everything, or keep the keys and keep the agent useless.

DefiMind removes that trade-off. The agent gets spending power. You keep the keys and a hard ceiling on what can go wrong.

03How it works

Every payment takes the same four steps, in the same order, on every chain.

  • Request. The agent asks DefiMind to pay. It holds no key and no money; asking is all it can do.
  • Policy. The payment is checked against the owner's rules: limits, chains, tokens, recipients and websites.
  • Test run. The exact transaction is simulated against the real chain. If it would do anything the request did not describe, it never runs.
  • Decide. Under the owner's threshold it is paid. At or above it, it waits for the owner's passkey. Anything that breaks a rule is rejected with a named reason.

04Architecture

Money flows through four layers. Each one narrows what the one above it can do.

Owner vault — holds the funds. Squads v4 on Solana, Safe on EVM chains. Only the owner controls it.
Onchain spend limit — refills the spending wallet, never above the daily cap. enforced by the chain, not by us
Spending wallet — a small balance the agent spends from. Its key lives only inside the guard service, never logged, never returned.
Payments — x402 pay-per-use APIs and transfers, only to recipients and websites the owner allowed.

The agent talks to DefiMind over MCP, so one connection works with any agent on any platform. It gets four tools: paid_fetch, transfer, get_budget and check_intent. Each chain sits behind one adapter, so every chain gets the same policy, the same test run and the same kill switch. Adding a chain means adding an adapter, not rebuilding the product.

05Onchain guarantees

DefiMind deploys no smart contract of its own. The daily limit uses building blocks that already secure large amounts onchain and are independently audited by their own makers: the Squads Spending Limit on Solana, and the Safe Allowance Module on EVM chains, reset every 24 hours. The vault refills the spending wallet up to the daily cap and no more, and the chain enforces that whatever our software does.

Maximum loss per day = daily cap + spending wallet balance.

This holds even if the guard itself has a bug or is fully compromised. The cap starts deliberately low and rises only after weeks without incident. The owner can remove the limit entirely at any time with one signature.

06The policy engine

A new agent starts at deny-all and can spend nothing until the owner allows it. From there, the owner decides exactly how much freedom it gets.

  • Per-payment and daily limits — a ceiling on each payment and on the day's total, beneath the onchain cap.
  • Allowlists — which chains, tokens, recipients and websites are permitted. Empty means deny.
  • Approval threshold — any payment at or above it waits for the owner.
  • Task budgets — a budget for one job, for a set time, that the agent cannot exceed.
  • Pause — one switch stops an agent, or every agent at once.

What the agent says, its reason, the URL, an API's reply, is shown to the owner but never used to decide. Amounts are exact integers end to end: a value that would need rounding is refused, never rounded.

07Simulation and threat detection

A payment that passes policy is test-run against the real chain before signing. The guard reads the exact transaction, sees what it would really do, and refuses anything that differs from what was asked, with a named reject code written to the audit log.

Scope Reject code Meaning
All chains PER_TX_EXCEEDED · DAILY_EXCEEDED Over a limit you set.
All chains RECIPIENT_NOT_ALLOWED · DOMAIN_NOT_ALLOWED A destination you did not approve.
All chains SIM_UNEXPECTED_EFFECT The test run shows an effect the request never described.
Solana DELEGATE_DETECTED · AUTHORITY_CHANGE_DETECTED A hidden permission grab or an account takeover.
EVM APPROVAL_DETECTED · PERMIT_DETECTED A hidden token approval or a signature that would allow later withdrawals.

Twenty reject codes in all, split into a shared core and per-chain sets. Default deny: any doubt is a rejection.

08The owner stays in charge

Payments at or above the owner's threshold wait in the DefiMind app, with a push to the phone and a plain summary of what the payment will do. The owner approves with a passkey, their face or fingerprint, or rejects. An approval pays once, for exactly that chain, token, amount, recipient and website, and expires after ten minutes if nobody answers. Nothing is ever paid by default.

One button, Stop everything, pauses every agent at once and prepares, for each chain, the transaction that sets the spending limit to zero. The owner signs it and the vault is sealed. The kill has been rehearsed on mainnet.

10Built for the whole market

  • For builders. Give your agent a wallet without giving it your keys. One MCP connection, four tools, and every payment arrives already checked, simulated and within budget.
  • For users. Let an agent work for you around the clock, knowing the worst day is fixed in advance and every big payment waits for your face or fingerprint.
  • For the ecosystem. Every API, protocol and service that wants agents as customers needs agents that can pay safely. DefiMind is the guardrail that turns agent spending from a risk into a feature, on every chain it reaches.

As agents move from talking to transacting, the question every owner asks is the same: what stops it from spending what it should not? DefiMind is built to be that answer.
